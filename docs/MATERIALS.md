## 3. 每份材料怎么做

### 01 项目说明书（PDF）

比赛要求：说明项目目标、Agent Demo 功能、系统设计、当前进展和后续计划。评审标准是**技术实现、场景契合度、工程完成度、展示效果**，每一章都要让评委能对上其中一项。

建议 10–15 页，大纲和素材来源：

| 章节 | 内容 | 素材来源 |
|---|---|---|
| 1. 项目目标 | 复旦同学的信息痛点；现有方案调研（单点工具很多、通用助理不懂复旦）；我们的定位 | PRD §2、§2.4 |
| 2. 产品与 Agent 功能 | 一个主对话 + 动态 / 目标 / 资源库 / 搜索；早安、跟进、记忆、引用到对话；核心场景配截图 | PRD §1.4、§3.2、§5；F2 的截图 |
| 3. 系统设计 | 四层架构图；UIS 统一认证；课程总表；MCP 连接层；主动引擎（参考 dsh-superagent）；模型路由 | PRD §7 |
| 4. 差异化与创新点 | 四个创新点 + 对比表 + 给评委的一句话 | PRD §1.5 |
| 5. 当前进展 | 已完成的功能清单；真实接入情况（P 的实测结论）；测试结果（准确率、打扰次数减少比例）；截图 | DEVELOPMENT.md §1；AI 和 P 给的数据 |
| 6. 后续计划 | 决赛前路线图 | PRD §8.4 |
| 7. 合规与隐私 | 不保存 UIS 密码、只读、数据不出本机、演示使用虚构数据 | PRD §9 |
| 8. 参考与致谢 | 参考的开源项目（含 dsh-superagent）、使用的 AI 编程工具 | PRD §2.4 |

写作建议：

- **每章先说结论，再说细节。** 评委时间有限。
- 架构图可以用 PRD 里的 mermaid 图（在 GitHub 上能直接看到渲染结果），也可以用 draw.io 重画得更好看。
- 「当前进展」只写真实做到的。没跑通的写成「已设计、实测中遇到 XX 限制」，不要夸大。
- 全文统一用词：主对话、动态、目标、资源库、搜索、主动引擎、注意力预算、课程总表、MCP 连接层。

### 02 演示视频（mp4）

- 时长 3–5 分钟，1080p，带字幕；配音或字幕至少有一样，建议都有。
- 分镜以 PRD §12.5 为底稿，11/4 前细化成「每个镜头：画面 + 操作 + 配音词 + 时长」的表格，发群里给 L 和 F1 确认。
- 录屏：F1 按分镜操作，用 OBS 或系统自带录屏；每个镜头录 2 遍以上。
- 剪辑：剪映即可。开头 10 秒内说清楚「这是什么、解决什么问题」；结尾给出一句话总结和架构图。
- **只使用演示模式的虚构数据**。画面里不能出现真实姓名、学号、邮件、API Key。录完逐帧检查一遍设置页。
- 「设置 → 开发者」里有几个演示按钮（助教发来补充邮件、交掉作业、切换到考试周前），对应视频里的关键镜头。

### 03 视频说明

一张表：时间段 → 展示的功能 → 对应的创新点或评审标准。再加一段话说明「视频使用演示模式，数据均为虚构；真实接入情况见说明书第 5 章」。

### 04 代码

问 L：提交仓库链接（仓库需要公开或给评委权限）还是提交源码压缩包。如果提交源码，**不要包含 `node_modules/`、`out/`、`release/`**。

### 05 代码运行说明

P 会给你技术内容，你负责排版成评委能照着做的文档：运行环境 → 安装步骤 → 演示模式启动 → 真实使用的配置（模型、复旦账号、邮箱）→ 常见问题。每一步配一张截图更好。

### 06 补充材料

- 测试样例（你标注的 40 封邮件）+ AI 给的准确率表格
- 本地模型推理数据（如果 AI 实测可用）
- 全部界面截图
- 现有方案调研表（PRD §2.4 的表格，可以补充截图）

## 4. 测试邮件样例的格式

这些样例用来测量「邮件分类、截止时间抽取、邮件与作业关联」的准确率，是证明工程完成度的数据。**全部内容必须虚构**，不要复制真实邮件。

用表格（Excel 或在线表格）写，每封邮件一行：

| 列 | 说明 | 例子 |
|---|---|---|
| 编号 | M001、M002… | M001 |
| 发件人姓名 | 虚构 | 李助教 |
| 发件人邮箱 | 虚构；课程的老师和助教请用第 5 节表里的邮箱 | li.zhujiao@m.fudan.edu.cn |
| 主题 | | 关于 Lab 5 提交要求的补充说明 |
| 正文 | 50–300 字，写得像真的 | 各位同学：Lab 5 除了源码外… |
| 发送时间 | 2026-11-01 到 2026-11-07 之间 | 2026-11-03 21:13 |
| 标注：分类 | 五选一：**需回复** / **需处理** / **课程相关** / **校园通知** / **其他** | 课程相关 |
| 标注：截止时间 | 邮件里提到的截止时间，没有就空着 | 2026-11-03 23:59 |
| 标注：相关课程 | 第 5 节表里的课程名，没有就空着 | 数据结构 |
| 标注：相关作业 | 第 5 节表里的作业名，没有就空着 | Lab 5：链表与栈 |

分类怎么判断：

- **需回复**：发件人在等你的答复（「是否方便参加」「请回复确认」）。
- **需处理**：要你做某件事，但不用回信（「请于 11 月 10 日前登录系统确认」）。
- **课程相关**：某门课的作业、考试、课程安排。
- **校园通知**：讲座、交换、奖学金、竞赛、招聘宣讲等。
- **其他**：广告、订阅、系统通知等。
- 一封邮件只标一个最主要的分类。拿不准的在表格里加备注。

40 封的分布建议：需回复 6、需处理 8、课程相关 12、校园通知 8、其他 6。请有意加入一些**难一点的情况**：英文邮件、转发的邮件、通知里带截止时间、看起来像课程但其实是讲座、同一门课的不同作业。
